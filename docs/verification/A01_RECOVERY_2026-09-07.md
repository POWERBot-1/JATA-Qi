## 2. Hang investigation (bounded process inspection)

- `ps`, `/proc/*/cmdline`, and listening-port scan: **no node/npm/psql/postgres processes exist**. Nothing to terminate; no orphaned children remain.
- The sandbox container was **restarted** (systemd start 11:06, repository freshly cloned 11:07; reflog contains only `clone` + `checkout`). The previously running `npm test` died with the container; the orchestration layer's wait on that child process was therefore stale.
- **Root-cause mechanism (deterministic stall):** the `embedded-postgres@18.4.0-beta.17` wrapper (`node_modules/embedded-postgres/dist/index.js`, `initialise()`) spawns `initdb` and attaches only `stdout`/`stderr`/`'close'` handlers — **no `'error'` handler**. If the binary cannot be launched in a broken environment, the promise never settles, so `ensureServer()` in `packages/*/test/pg-harness.ts` hangs forever and the whole suite stalls. The missing-libpq condition observed in the stalled environment is the trigger; the wrapper defect converts a broken startup into an indefinite hang instead of a loud failure. No repository file needed changing to remove the trigger (see §3).
